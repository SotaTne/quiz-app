| cac-001 | ノイマン型コンピュータの主要な特徴を説明せよ。 | CPUと主メモリを持ち、命令とデータを主メモリに置き、基本命令を原則逐次実行する | 固定的な命令セットと線形メモリも重要。 |
| cac-002 | プログラムを補助記憶装置上のままCPUが直接実行しないのはなぜか。 | 実行する命令を主メモリへロードしてCPUがフェッチする方式だから | プログラム内蔵方式の基本。 |
| cac-003 | 命令セットとプログラムの違いを説明せよ。 | 命令セットは使える命令の種類、プログラムはそれらを並べた命令列 | 辞書と文章の関係に近い。 |
| cac-004 | 線形メモリの「線形」は数学の線形性と何が違うか。 | アドレスが一次元に連続して並ぶことを指し、関数の線形性ではない | 微分可能性とも無関係。 |
| cac-005 | CPU、主メモリ、補助記憶装置の役割を説明せよ。 | CPUは命令実行、主メモリは実行中の命令とデータ保持、補助記憶装置は長期保存を担う | 速度、容量、揮発性が異なる。 |
| cac-006 | PC、IR、MARの違いを説明せよ。 | PCは次の命令位置、IRは現在の命令、MARは今回アクセスするメモリアドレスを保持する | 3つの混同は頻出。 |
| cac-007 | ALUと制御装置の違いを説明せよ。 | ALUは演算し、制御装置は命令を解読して各部を指揮する | 演算する部署と司令する部署。 |
| cac-008 | レジスタと主メモリの違いを説明せよ。 | レジスタはCPU内部で高速・小容量、主メモリは外部で比較的大容量・低速 | 用途も一時値と実行中プログラムで異なる。 |
| cac-009 | 命令実行の5段階を順に説明せよ。 | フェッチ、デコード、オペランド取得、実行、書き戻し | PC、IR、デコーダ、ALU、レジスタやメモリに対応する。 |
| cac-010 | 命令フェッチ時のPC、MAR、IRの流れを説明せよ。 | PCのアドレスをMARへ渡し、そのメモリから読んだ命令をIRへ入れる | その後PCは次の命令位置へ更新される。 |
| cac-011 | PCが通常は命令長だけ増える理由を説明せよ。 | メモリ上で次の命令が現在の命令の直後に置かれるから | 分岐時は分岐先アドレスへ置き換わる。 |
| cac-012 | 命令デコードが必要な理由を説明せよ。 | bit列だけでは各回路が何をすべきか分からず、オペコードを制御信号へ変換する必要があるから | ALUの演算種類などを指定する。 |
| cac-013 | 書き戻しが実行と別段階である理由を説明せよ。 | ALUが結果を生成することと、その結果を保存先へ格納することは別の動作だから | 結果はレジスタまたはメモリへ保存される。 |
| cac-014 | ノイマン・ボトルネックでCPUだけを高速化しても限界がある理由を説明せよ。 | 主メモリから命令とデータを供給する転送速度が変わらずCPUに待ちが生じるから | バスやメモリ帯域が制約になる。 |
| cac-015 | 1本の信号線と1byteのメモリ位置を区別して説明せよ。 | 1本の線は通常1bitを運び、byte-addressableな1アドレス位置は8bitを保持する | 信号線の本数とアドレス単位は別概念。 |
| cac-016 | 明示的オペランドと暗黙的オペランドの長短を説明せよ。 | 明示型は分かりやすいが命令が長くなり、暗黙型は短いが位置が命令だけでは分かりにくい | 命令形式のトレードオフ。 |
| cac-017 | スタック型でADDにオペランドを書かなくてよい理由を説明せよ。 | 演算対象がスタックトップの2値、結果位置もトップと規則で決まるから | オペランドが暗黙的。 |
| cac-018 | `C=A+B`をスタック型の命令列で表せ。 | PUSH A、PUSH B、ADD、POP C | 後置記法$AB+$と対応する。 |
| cac-019 | `C=A+B`をアキュムレータ型の命令列で表せ。 | LOAD A、ADD B、STORE C | アキュムレータを暗黙に使う。 |
| cac-020 | `C=A+B`をレジスタ・レジスタ型の命令列で表せ。 | LOAD R1,A、LOAD R2,B、ADD R3,R1,R2、STORE C,R3 | ALU命令はメモリを直接扱わない。 |
| cac-021 | レジスタ・メモリ型とレジスタ・レジスタ型の違いを説明せよ。 | 前者はALU命令でメモリを直接扱え、後者はLOADとSTORE以外ではメモリを扱わない | 命令数と単純さのトレードオフ。 |
| cac-022 | 後置記法がスタック処理に適する理由を説明せよ。 | オペランドを積み、演算子が来たら必要数をPOPして結果をPUSHすればよいから | 括弧なしでも順番に評価できる。 |
| cac-023 | RISCとCISCの設計上の違いを説明せよ。 | RISCは単純で規則的な命令、CISCは複雑で高機能な命令を重視する | 現代CPUは両者の技術を取り入れる。 |
| cac-024 | RISCでICが増えても性能が上がり得る理由を説明せよ。 | 命令単純化によりCPIやクロック周期を小さくできる可能性があるから | CPU時間はICだけで決まらない。 |
| cac-025 | CISCでICが減っても性能が下がり得る理由を説明せよ。 | 複雑な命令によりCPIやクロック周期が増える可能性があるから | 定量評価が必要。 |
| cac-026 | ロード・ストア方式が制御やパイプラインに向く理由を説明せよ。 | ALU命令とメモリアクセスを分離し、命令動作を規則的にできるから | RISCの典型的特徴。 |
| cac-027 | 論理右シフトと算術右シフトの違いを説明せよ。 | 論理は上位を0で埋め、算術は符号bitで埋める | 符号付き値では結果が異なる。 |
| cac-028 | bitのセット、クリア、トグル、テストの違いを説明せよ。 | セットは1、クリアは0、トグルは反転、テストは状態判定 | 先生が整理した基本bit操作。 |
| cac-029 | 特権命令を一般プログラムに許さない理由を説明せよ。 | システム全体や他プログラムを破壊する操作を防ぐため | OSが資源を安全に管理する。 |
| cac-030 | SVCと割込みの関係を説明せよ。 | SVCはプログラムが意図的にOS処理を要求し、割込み機構に似た制御移行を起こす | 外部装置の割込みとは発生原因が異なる。 |
| cac-031 | マルチコアとマルチプロセッサの違いを説明せよ。 | マルチコアは1チップ内に複数コア、マルチプロセッサはシステムに複数プロセッサを持つ | 広義の用語では重なりもある。 |
| cac-032 | コア数に比例して必ず高速化しない理由を3つ答えよ。 | 逐次部分、データ依存、共有メモリやバスの競合 | プログラム側の並列性も必要。 |
| cac-033 | スループットとレスポンスタイムの違いを説明せよ。 | スループットは単位時間の仕事量、レスポンスタイムは1仕事の完了時間 | 前者は大、後者は小がよい。 |
| cac-034 | Elapsed TimeとCPU時間の違いを説明せよ。 | Elapsed Timeは待ちを含む経過時間全体、CPU時間はCPUが処理に使った時間 | 性能式が直接扱うのはCPU時間。 |
| cac-035 | ICだけでCPU性能を比較できない理由を説明せよ。 | CPIとクロック周期もCPU時間を左右するから | $T_{CPU}=IC\times CPI\times TPC$で比較する。 |

| cac-038 | 使用率のポイント値の合計が1でない場合に必要な処理は何か。 | 各ポイントを全ポイント合計で割って正規化する | 先生が計算上の注意として明示した。 |
| cac-039 | 単一ベンチマークだけで評価する問題点を説明せよ。 | 特定の処理への得意不得意に結果が偏るから | 複数のベンチマーク・スイートを使う。 |
| cac-040 | ROMとRAMが対立概念ではない理由を説明せよ。 | ROMは読み書き特性、RAMはアクセス方法を表す別の分類軸だから | ROMの対はRWMやWORM、RAMの対はSAM。 |
| cac-041 | ROMとOSの読み取り専用権限の違いを説明せよ。 | ROMは記憶媒体・素子の特性、権限はOSが設定するアクセス制御 | 別プロセスなら書けるという意味のROMではない。 |
| cac-042 | SRAMがキャッシュ、DRAMが主メモリに向く理由を説明せよ。 | SRAMは高速だが高価・低密度、DRAMは比較的低速だが安価・高密度だから | 速度・容量・コストを適材適所で使う。 |
| cac-043 | 理想的な単一メモリが実現困難な理由を説明せよ。 | 高速・大容量・低コストを同時に最大化できないから | メモリ階層を構成する理由。 |

| cac-045 | 時間的局所性と空間的局所性の違いを説明せよ。 | 時間的は同じ場所の再参照、空間的は近い場所の連続参照が起きやすい性質 | キャッシュの根拠。 |
