# 授業動画から講義資料を作る

## 目的

1授業につき、次の3つを入力として扱う。

- ユーザーが事前に用意した音声認識Markdown（例: `01audio.md`）
- `video1.mp4`
- `video2.mp4`

音声の文字起こしはこのスキルでは実行せず、ユーザーが用意した音声Markdownを使う。動画は音声のない画面録画であることが多いため、markitdownで動画全体を処理せず、FFmpegで90秒ごとに1枚のフレームを抽出して、エージェントが画像を直接確認する。

この3つから次の2つを作る。

- `video.md`: 動画の映像を時系列に記録した資料。90秒ごとのフレームを確認し、画面上の内容をできるだけそのまま書く。
- `note.md`: カンペ兼レジュメ。これだけ読めば、その回の授業内容・流れ・説明・例を理解でき、授業動画を見ながら参照できる資料。
- `words.md`: その回の授業に実際に登場した用語の表。

## 必須ワークフロー

### 1. 入力を確認する

授業フォルダ内の次を確認する。

```text
*audio.md
video1.mp4
video2.mp4
```

番号は音声Markdownの番号をそのまま使う。動画が複数ある場合も、勝手に別授業として分割しない。

### 2. 動画から確認用フレームを作る

各動画について、90秒ごとに1枚のJPEGを抽出する。元動画は変更しない。

```bash
ffmpeg -i video1.mp4 -vf "fps=1/90,scale=1600:-1" frames/video1-%03d.jpg
ffmpeg -i video2.mp4 -vf "fps=1/90,scale=1600:-1" frames/video2-%03d.jpg
```

抽出したフレームは画像として直接確認する。OCRだけに依存せず、スライド、板書、図、矢印、表、画面上の文字の位置関係も読む。フレーム番号からおおよその時刻をnote.mdに記録する。

動画に音声ストリームがない場合は正常な構成として扱う。音声は別ファイルのユーザー提供Markdownから取得する。フレーム抽出や画像確認が失敗した場合は記録し、音声Markdownだけから映像内容を推測してはならない。

### 3. 3つの入力を突き合わせる

内容の採用優先順位は次の通り。

1. 音声Markdownで講師が実際に話した内容
2. video1/video2から90秒ごとに抽出したフレームで直接確認できるスライド、板書、図、表、画面上の文字
3. 音声と映像の両方から自然に確認できる授業の構造

教科書や一般知識で補足する場合は、授業で扱われた内容と明確に分ける。授業で扱っていない説明、別回の内容、一般的な用語解説をnote.mdへ混ぜない。

#### 3.1 音声Markdownを読む前に整形する

ユーザー提供の音声認識Markdown（`NNaudio.md`）は、句読点はあっても改行がなく、ファイル全体が1〜数行の巨大なテキストになっていることが多い。この状態では`Read`のoffset/limitでページングできず、全文を読まずに要約してしまう原因になる。

読む前に、内容を一切変えずに句点（。？！）の後で改行を入れた整形版を**同じフォルダに別ファイルとして**作成する（元の`NNaudio.md`は変更しない）。

```bash
# 例: 01audio.md → 01audio.formatted.md（内容は不変、句点ごとの改行のみ追加）
python3 -c "
import re
text = open('01audio.md', encoding='utf-8').read()
text = re.sub(r'([。？！])\s*', r'\1\n', text)
open('01audio.formatted.md', 'w', encoding='utf-8').write(text)
"
```

作成後、変換前後で空白を除いた文字列が一致することを確認し（内容が変わっていないことの検証）、`01audio.formatted.md`を`Read`で**オフセットを進めながら最初から最後まで全文読む**。音声Markdownは長いため、video.mdやその場の推測だけで済ませず、必ず全文に目を通してから note.md を書く。

#### 3.2 雑談・事務連絡と実質的な講義内容を区別する

授業冒頭には、シラバス確認、著作権・利用規約の説明、Moodle操作、出欠確認、次回の予定連絡など、学問的内容を含まない雑談・事務連絡が長く続くことがある。これらは note.md の「3. 時系列カンペ」で要点を1〜数行に圧縮し（例：「著作権上の利用制限の説明、Moodle資料の案内、教科書購入案内など」）、実質的な講義内容（定義・仕組み・具体例・数式）に紙面を割く。省略した旨と、詳細が必要な場合の参照先（video.mdの該当セクション）を明記する。

雑談を削ることと、実質的な内容を薄くすることは別である。ある用語について講師の説明が「用語を読み上げただけ」で終わっている場合、それをnote.md側で一般知識で水増ししてはならない。実際の説明量の薄さをそのまま反映し、必要なら「講師の説明は用語提示のみで、内容の踏み込んだ説明は行っていない」と明記する。

### 4. video.mdを作る

`video.md`は要約ではなく、映像の記録である。90秒ごとのフレームについて、次を時系列でできるだけ具体的に書く。

- スライドや板書の見出し・本文・箇条書き・式・図中の文字
- 図、表、矢印、枠、配置、強調、カーソル、ページ番号
- 写真や画像が表示された場合の内容説明（何が写っているか、授業上どのように見えるか）
- 画面が前のフレームと実質的に同じ場合は、全文を繰り返さず「前フレームから変化なし」と記録
- 読めない文字は推測せず `[判読不能]` と記録

画像の説明は、画像そのものから確認できる範囲に限定する。写真の背景や人物の属性など、画像から判断できない内容を推測しない。`video.md`は、この資料だけを見れば動画の画面遷移を追える粒度にする。

### 5. note.mdを作る

`note.md`は単なる要約や汎用テンプレートではなく、その回専用の視聴用カンペにする。「音声を読んで感想を書く」のではなく、**授業で実際に語られた定義・数値・式・具体例そのもの**を書き写す。「〜について説明している」「個別の数値は資料と照合する必要がある」のような、中身を指し示すだけで中身自体を書かない記述は禁止。読んだだけでその回の授業を再現できる密度が目標であり、これができていなければ書き直す。

少なくとも次を含める。

- 授業タイトル、日付、時間、対象ファイル
- 授業の最初から最後までの時系列（雑談・事務連絡は3.2節の方針に従い圧縮する）
- 各区間で講師が何を説明したか（要約ではなく、実際の言い回し・定義・数値そのもの）
- 定義、仕組み、比較、手順、式、数値
- 講師が使った具体例・比喩・図の読み方
- スライド・板書に表示された語句や図表
- 「ここで押さえること」の短い確認欄（試験直前に読んで自己採点できる形式。下記参照）
- 音声由来、映像由来、両方で確認できる内容の区別
- 聞き取り不明、映像で読めない箇所、解釈が分かれる箇所

推奨構成は次の通り。

```markdown
# 授業タイトル
## 0. この回を一言で
## 1. 視聴前に確認する語
## 2. 授業の流れ
## 3. 時系列カンペ
### 3.1 ...
### 3.2 ...
## 4. 仕組み・定義・式
## 5. 授業中の具体例
## 6. スライド・板書で確認できるもの
## 7. この回の要点（試験直前チェックリスト）
## 8. 不明箇所と根拠の区別
```

`note.md`だけで授業の内容を理解できるようにする。ただし、授業で実際に扱われた範囲を越えて説明を膨らませない。一般知識による補完が必要な場合は「授業外の補足」と明記する。

#### 5.1 数式の書式

本文中に数式・式変形が登場した場合は、地の文にプレーンテキストで埋め込まず、必ずLaTeX記法で書く。行内は `$ ... $`、独立した式は `$$ ... $$` で囲む。

```markdown
多項式の一般形：

$$
P(n) = \sum_{i=0}^{n} a_i x^i
$$

線形性の条件は $f(a \cdot x) = a \cdot f(x)$ と $f(b+c) = f(b) + f(c)$ の2つ。
```

video.mdに記録された板書の数式・記号（Σ、添字、上付き文字など）を漏らさずLaTeXへ起こす。読み取れない部分は数式内でも`[判読不能]`を用いる。

#### 5.2 「この回の要点」は試験直前チェックリストにする

7節は単なる箇条書きの感想ではなく、読者が自分で答えられるかを確認できる一問一答形式（表）にする。

```markdown
| # | 問い | 答え |
|---|---|---|
| 1 | 〜とは何か | 〜（定義そのもの） |
| 2 | 〜の名称の由来は | 〜 |
```

加えて、講師が誤字・誤解を名指しで注意した点、記述式で問われやすい定義の組み合わせなどを「記述式で狙われやすいポイント」として別途まとめる。

#### 5.3 音声認識の誤変換への対応

音声Markdownは自動認識のため、専門用語が同音の別語に誤変換されていることが多い（例：「線形」→「先形」、「半導体」→「反動体」、「本書」→「本省」）。文脈・板書内容（video.md）と整合する場合は正しい語に訂正してnote.md本文に書いてよいが、**訂正した旨と根拠を8節に明記する**。確信が持てない場合は本文に採用せず、8節に候補として記録するに留める。

#### 5.4 一般知識・検索による補完

音声・映像のどちらにも情報がなく、かつ一般的な教科書知識や検索で解決できる場合は、補完してよい。ただし次を厳守する。

- 該当箇所に「**一般知識による補足（授業外）**」等と明記し、講師の発言や板書内容と区別する。
- 講師が名言・断定していない事項（人物名、文献名など）を、一般知識側からも断定できない場合は「〜の可能性が高いが講師は明言していない」のように確度を残す。
- 一般知識で補うのは、音声・映像に手がかりが実在するがあいまいな場合に限る。授業で全く触れられていない話題を新規に付け足すことは禁止。

### 6. words.mdを作る

その回の音声・動画に実際に登場した用語だけを記載する。専門用語を一般的な知識から水増ししない。聞き取りにくい語は確定語として書かず、候補または不明として扱う。

表の列は固定する。

```markdown
| 用語 | 読み方・英語 | 分類 | 授業での意味・説明 | 関連概念 | 登場した文脈・補足 |
|---|---|---|---|---|---|
```

同じ授業でも、講師が例として挙げた一般語、略語、スライドの見出し、図中のラベルを含める。ただし「授業に関係しそう」という理由だけで未登場語を追加しない。

## 禁止事項

- 音声Markdownだけを使って動画内容を推測する
- `video.md`を作らずにnote.mdやwords.mdを作る
- 動画を処理せず、映像内容がわかったように書く
- 別の授業回の内容を混ぜる
- 教科書の一般論を講師の発言として書く
- 不明な数値・式・図中文字を推定して確定扱いする
- note.mdを「ISAとは何か」のような一般解説だけで埋める
- 3つのMarkdownを単に連結して、授業の流れを整理しない
- note.mdを「〜について説明している」「〜を参照しながら」のような、内容そのものを書かずに存在だけを指し示す記述で埋める（音声を読んだ感想文にしない）
- 音声Markdownを全文読まずに、video.mdや部分的な閲覧だけでnote.mdを書く
- 数式をプレーンテキストのまま書き、LaTeX（`$...$`/`$$...$$`）に起こさない
- 講師の説明が薄い箇所を、一般知識で目立たないように水増しして均質に見せる

## 成果物の配置例

```text
授業フォルダ/
├── 01audio.md                 # ユーザーが用意した音声認識結果
├── video1.mp4
├── video2.mp4
└── frames/                    # 90秒ごとの確認用フレーム

CA/01/
├── video.md
├── note.md
└── words.md
```

作成後、video.mdが2本の動画のフレームを時系列に記録しているか、note.mdとwords.mdが音声Markdownとvideo.mdに基づいているか、授業外の内容を混ぜていないかを確認する。
